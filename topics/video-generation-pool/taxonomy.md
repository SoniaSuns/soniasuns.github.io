# Video Generation 论文池：标注规则 v1

制定日期：2026-10-14；先于逐篇标注。以下是本研究的操作性分类规则 [推断]，不是论文作者共同采用的标准。论文事实与定位证据另记在 papers.csv；没有明确证据的属性不补猜。

## 单选、主次与不确定

任务由论文要解决的输入—输出契约决定，不由标题词或采用的技术决定；benchmark、dataset 按其服务的任务归类。主贡献取作者核心新机制，其他有明确新意的机制作为次贡献；使用现成 VAE 不自动构成“表示”贡献，做消融不自动构成“评测”贡献。矩阵只统计主贡献，每篇恰好计一次；次贡献另存，可用于理解相邻工作。宽泛 quality/consistency 不自动扩展为因果或几何一致。

有源视频且要求受限改动，优先“编辑与修改”；动作驱动环境状态演化优先“动作条件的预测与交互世界模型”；只有相机轨迹但以跨视角重建/重访为核心，优先“3D/4D 一致生成”；长时间 prompt 切换而无环境动作契约归“长视频与多镜头叙事”。多事件时间控制不自动等同于多镜头叙事。仍无法确定时单选字段填“不确定”，在 uncertainty 字段列出两个候选及原因，不把不确定样本硬塞进“其他”。

## 1. 任务（主轴，单选）

|类别|一句纳入标准|边界例子|
|---|---|---|
|文本或图像生成视频|从文本或初始图像生成视频，以一般生成质量或语义匹配为主要任务契约。|仅提升 T2V 少步质量仍属此类；新增可独立指定相机路径的接口进入条件控制。|
|条件控制生成|除一般文本/初始图像外，提供可明确操控的运动、姿态、相机、音频、身份或事件时间条件来合成视频。|主体参考定制属于控制；要求改动一条给定源视频并保持其余内容则属编辑。|
|编辑与修改|输入已有视频或明确已生成历史，按修改请求改变部分内容并要求保留相关源内容。|首帧传播到源视频属编辑；只有初始图像和自由生成要求不是视频编辑。|
|长视频与多镜头叙事|核心任务要求长时间延展、跨镜头实体/故事连续或生成中持续更新文本叙事。|少步 AR 短片不是仅凭 AR 就归长视频；对象重访由环境动作驱动时归世界模型。|
|动作条件的预测与交互世界模型|根据环境观察/历史和显式或学习到的动作，预测未来视觉状态或支持交互 rollout。|latent action 也可纳入；只有相机新视角渲染且不建模环境动作后果，优先 3D/4D。|
|3D/4D 一致生成|任务核心是多个视角或时间下共享几何世界的生成、重建、再渲染或场景重访。|内部使用 3D 只为单条视频控制，不足以自动纳入；输出可仍为 2D 视频。|
|视频作为推理或回答|生成的视频本身承担问题答案、规划轨迹或规则可验证的解题过程。|给定动作预测未来环境不自动是解题；需要满足迷宫目标或回答用户问题才纳入。|
|其他（说明）|论文的主要输入—输出契约确实不能归入上述七类，并写明未覆盖的任务。|未读清楚不能填其他，必须填不确定并列候选。|

## 2. 贡献落点（主 1、次可多）

|类别|一句纳入标准|边界例子|
|---|---|---|
|表示|提出或改变 latent、3D/4D、结构化脚本/场景图或离散 token 等被模型计算的表示。|新空间分解或可学习 latent action 属表示；直接使用已有深度图作条件不一定属表示。|
|条件注入|改变控制信息的编码、融合、注意力接入或与生成器对齐方式。|新相机 adapter 属条件注入；仅更换控制数据但接口不变主要是数据。|
|架构与生成范式|改变 backbone、注意力结构、因果分解或生成/去噪计算组织。|稀疏 attention 属架构；只有新蒸馏 loss 则主归训练信号。|
|记忆与上下文|改变历史信息的存储、更新、压缩、检索或失效处理机制。|有几何索引的视图检索属记忆；固定多帧拼接不自动构成新记忆机制。|
|训练信号|提出监督目标、reward、偏好学习、RL、蒸馏或训练分布/rollout 监督方式。|以自己的历史 rollout 接受序列损失属训练信号；冻结模型采样时打分不属训练。|
|推理时方法|核心方法冻结被控生成器权重，在推理时 guidance、搜索、校验或重采样。|额外训练 reward 后用于冻结生成器的搜索可主归推理；生成器 RL 更新归训练信号。|
|数据|核心产出是新数据集、配对数据构建、标注方案或可扩展数据引擎。|使用合成数据辅助方法并不必然主归数据，但有新数据构建可列次贡献。|
|评测|核心产出是新 benchmark、指标或可复用评测协议。|报告已有 FVD 不构成评测贡献；新 benchmark 及其验证属于评测。|

## 3. 控制信号（多选）

|类别|一句纳入标准|边界例子|
|---|---|---|
|文本|推理时接收语言描述、指令或结构化文字条件。|训练 captions 但推理不接收文本时不标。|
|图像|推理时接收图像、源视频帧或历史视觉观察。|明确包含源视频/历史帧；内部生成的噪声 latent 不是图像控制。|
|相机|推理时明确输入相机姿态、外参、位姿或相机运动命令。|文本说“镜头向左”而没有相机控制接口，仅标文本。|
|轨迹或光流|推理时接收对象/点轨迹、运动场或光流。|模型内部从文本生成轨迹且交给生成器时，记录为派生控制并注明。|
|姿态或结构图|推理时接收人体/手/脸关键点、分割、深度或其他空间结构图。|普通参考照片不是姿态；深度作为内部推断中间量需注明派生。|
|动作|推理时接收按键、机器人控制量、驾驶控制或 learned latent action。|对象轨迹本身不自动等同于 agent/environment action。|
|音频|推理时接收声音、语音或音乐驱动视频内容。|只有生成输出中的音轨不算音频控制。|
|物理或模拟代理|推理流程明确输入力、力矩、物理参数或模拟器生成的状态/渲染控制。|论文说物理合理但没有物理控制接口时不标。|
|身份参考|用参考图像/视频或定制实例明确约束主体身份。|任意初始图像不自动作为身份参考；明确身份保持或 subject customization 才标。|
|无|对象是纯数据/评分协议且不定义生成器控制输入，或明确无条件生成。|对 T2V 输出打分的 reward model 如任务契约仍接收文本，则标文本而非无。|

## 4. 目标性质（多选）

|类别|一句纳入标准|边界例子|
|---|---|---|
|画质|明确优化或评价视觉保真度、美学、清晰度或感知质量。|任务准确率本身不等同画质。|
|短时连贯|明确处理相邻帧闪烁、局部运动平滑或连续性。|长时实体相同不必然证明局部平滑。|
|实体一致|明确约束主体、物体或地点的身份/外观保持。|CLIP 文本相似度不能单独证明实体一致。|
|几何一致|明确约束跨视角的几何、布局或 3D/4D 对应关系。|视觉上连贯但无几何要求时不标。|
|环境记忆|明确要求重访、长期保存或检索环境历史状态。|短上下文 attention 不是自动的长期环境记忆。|
|因果或状态一致|明确要求动作/事件后状态转移、前置条件、持久后果或规则逻辑相容。|因果 attention 仅指计算方向，不能据此标因果一致。|
|物理合理|明确要求力学、接触、物质行为或真实物理规律合理。|真实感/FVD 提升不自动证明物理合理。|
|指令遵循|明确要求输出符合文本、编辑、动作或其他控制请求。|视频质量高但没测请求是否执行，不据此推断遵循提高。|
|效率与延迟|明确优化或衡量步数、吞吐、首帧/交互延迟、计算量或显存。|只称 lightweight 但无清楚效率目标时保留不确定。|

## 5. 生成范式（单选）

这三个选项混合了时间分解和计算预算两个轴。[推断] 为满足当前单选要求：论文以少步/实时为核心产出时优先标“少步或实时”，并在 paradigm_detail 保留是否因果 AR；否则明确逐帧/逐块输出标“因果自回归或流式”；余下明确联合生成一段标“离线整段生成”。benchmark、reward 或数据论文跨多种生成器时填不确定，并写候选及“非单一生成器”。不得把这种不确定当论文缺陷。

|类别|一句纳入标准|边界例子|
|---|---|---|
|离线整段生成|联合生成/编辑给定长度片段，未以少步或在线输出为核心契约。|将多段拼成长片但每段双向去噪时，注明块级离线。|
|因果自回归或流式|明确逐帧、逐 token 或逐块依赖过去输出，且少步/实时不是优先主张。|使用 causal mask 不意味着达到实时。|
|少步或实时|核心方法明确以少步采样或实时吞吐/响应为目标并给出相应结果。|必须另记硬件/设置边界；实时吞吐不等同零交互延迟。|

## 6. 论文类型（单选）

|类别|一句纳入标准|边界例子|
|---|---|---|
|方法|主要提出生成、训练、控制、记忆或推理算法。|同时建数据但算法是主要结论时仍为方法。|
|基准|主要提出用于比较能力的评测数据、任务、指标与协议。|有训练集的 benchmark 仍可归基准，不单按含数据决定。|
|数据集|主要发布支持训练/对齐的数据资产及其构建流程。|用 specialist 生成编辑训练对属于数据集。|
|分析|核心是控制变量实验、理论或机制分析，而非提出更强的新生成器。|含改进 baseline 不自动改变分析类型。|
|综述|系统组织既有研究并总结分类与趋势，而不以新方法/数据/实验结论为核心。|方法论文的 related work 不属于综述。|

## 逐篇补充字段与证据

input / output / invariants / correctness 四项构成任务定义。“必须保持”只写作者明示的设计约束；没有明确保持契约则写“未明确规定”，不将“看起来没变”补写为事实。

evidence_types 分别记录：定量 benchmark（具名数据/指标/表）；消融（改变组件或训练设置的对照）；user study（同时记录参与者 N、提示/视频/判断数量，不能混用）；仅定性展示（只有展示且未找到前三类时才能使用）。全文尚未获取或报告不清时写“不确定/未核实”，不能写“没有实验”。数据标注人数不自动等于用户实验人数；相关性验证的人类评价与生成结果偏好实验分开说明。

每篇保存 evidence_locator（正文节/表/PDF 页）和 evidence_url；保存阅读范围、全文取得状态与 uncertainty。中文一句话只概括本论文推进点；横向比较、任务归类边界和研究建议标 [推断]。不以摘要中“extensive experiments”代替具体实验核验。

## 综合时的计数与稀疏判断

矩阵每格列主贡献篇数及最多 3 篇代表论文；只有 1 篇就列 1 篇，空格列 0，不为了凑代表论文挪动样本。定义“稀疏”为 1–2 篇。逐格结合同任务相邻工作判断“池内覆盖不足”“定义/交叉主贡献导致”“存在实现障碍”或“任务与贡献不匹配”；不得从 0 推出无人做、做不了或不值得做。新颖性最多表述“在本论文池内未见”。
